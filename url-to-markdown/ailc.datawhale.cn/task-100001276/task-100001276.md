## 步骤一：准备一台不用自己配置的云电脑

### 1. 创建腾讯云 Cloud Studio 环境

部署 AgentTeams 需要使用 Docker 等工具，本地安装和配置对零基础学习者有一定门槛。为降低环境配置难度，本教程统一使用已预装开发环境的腾讯云 Cloud Studio。

#### 1.1 登录 Cloud Studio，并创建应用

打开：[腾讯云 Cloud Studio](https://cloudstudio.net/)，按照页面提示登录。

登录后，在页面右上角点击“创建应用”。模板选择 **All in One** ，然后点击“创建”。

![图片](imgs/img-002.png)

![图片](imgs/img-003.png)

![图片](imgs/img-004.png)

#### 1.2 检查机器配置 & AI 的使用

进入云环境后，看页面右上角的机器配置。如果不是 4 核 8 GB，点击配置区域的“切换”，换成 4 核 8 GB。

> 本教程使用：CPU：4 核内存：8 GB

在左侧有一个“ **⚡️** ”的按钮，点开可以使用AI来帮助处理问题。

![图片](imgs/img-005.png)

### 2. 配置自动关机

Cloud Studio并不一定会自动关闭。为了避免忘记关闭导致的费用超支， **建议设置定时关机** 。从0开始完整运行一次Demo的时间，预期是1小时，推荐设置2或4小时后关机。

![图片](imgs/img-006.png)

> 云环境关闭后，程序也会停止。需重新打开云环境使用。

## 步骤二：准备大模型 API Key

获取 DeepSeek API Key：AgentTeams 自己不是大模型，它需要通过 API 调用大模型。本教程使用 DeepSeek。

### 1. 登录

打开：[DeepSeek 开放平台](https://platform.deepseek.com)，按页面提示使用手机号、验证码或微信扫码登录。

### 2. 检查余额并进入 API Keys

进入控制台后，打开“API Keys”。如果账户余额不足，需要按自己的需要少量充值。跑一次demo做需要的消耗在1元以内，可以充个5元试试。

![图片](imgs/img-007.png)

### 3. 创建 API Key

（1）点击“创建 API Key”，名称只是个备注，可以任意填写。

（2）接下来会得到一个 API Key，请暂时不要关闭这个页面，后面安装 AgentTeams 时需要粘贴。

> API Key 相当于调用大模型的密码。请不要把自己的 Key 发到聊天群、GitHub Issue 或公开文档中。

### 1. 启动 Mock 工具服务

你可以把这个 Mock 工具服务理解成一台 **提前设置好故障的模拟业务服务器** 。它准备了“订单创建失败”和“订单历史页变慢”等故障场景。AgentTeams 会查询相关数据、分析根因、执行允许的模拟修复，并验证业务是否恢复。

启动这个服务后，AgentTeams 会像处理真实服务器故障一样，主动查询这些数据、寻找故障原因、制定并执行允许的模拟修复，最后检查业务是否恢复。这个 Demo 展示的是一套完整的“发现故障—分析根因—修复故障—验证恢复”流程，但不会改动任何真实生产服务器。

#### 1.1 新建一个终端

点击： `终端 → 新建终端`

#### 1.2 运行Mock服务

在新终端中执行：

```
cd /workspace/opspilot-zero-demo
python3 tools/mock_tool_server.py --host 0.0.0.0 --port 18089
```

如果成功，会看到：

![图片](imgs/img-022.png)

#### 1.3 这个终端不要关闭

只要 Demo 还没有跑完，就让这个终端保持运行。

不要在这个终端继续输入别的命令。需要执行其他命令时，点击终端右上角的 `+` ，再开一个新终端。

#### 可选：检查 Mock 服务

在另一个终端执行：

```
curl http://127.0.0.1:18089/health
```

如果看到包含下面内容的结果，表示服务正常：

```
{
  "ok": true,
  "service": "opspilot-mock-tool-gateway"
}
```

## 步骤五：创建 4 个 Agent 和 1 个 Team（大概 5 min）

### 1. 复制创建 Agent 和 Team 的消息

Manager 是管理整个 AgentTeams 的“最终 Boss”，负责接收你的管理指令、创建 Agent 组织团队。

Demo 已经把创建 4 个 Worker 和 1 个 Team 所需的内容写在同一个代码框里。你只需要把这个代码框复制一次，然后发送给 Manager 即可自动“安装”。

打开：

```
opspilot-zero-demo/at/create_agents_messages.md
```

在文件中复制这个大标题下面的 **全部内容** ：

```
## 复制到 Manager 的完整创建请求
```

### 2. 把完整创建请求发送给 Manager

回到 Element，打开： `Manager: default` ，把刚才代码框中的全部内容粘贴到 Manager 房间，发送一次即可。

> Manager 按下面的顺序执行：（1）创建 `alert-intake` ；（2）确认它创建成功并可以运行；（3）创建 `rca-analyst` ；（4）创建 `remediation-planner` ；（5）创建 `recovery-verifier` ；（6）确认 4 个 Worker 都可以运行；（7）最后创建 `opspilot-zero-demo` Team。

这些步骤由 Manager 自动依次完成。你不需要再次手动复制每个 Worker 的创建内容，也不要重复发送完整请求。

创建过程可能需要一些时间。Worker 创建后，会在 AgentTeams 界面中出现对应条目。创建成功后，再按如下操作。

## 步骤六：运行两次事故处理任务（大概 30 min）

4 个 Worker 和 `opspilot-zero-demo` Team 创建完成后，在 Element Web/Matrix 会话列表中找到名称以 `Team` 开头、对应 `opspilot-zero-demo` 的 Team 房间。

打开 `opspilot-zero-demo/at/create_agents_messages.md` ，把订单创建失败的事故任务处置任务复制好。

进入 Team 房间后，在输入框先输入并选中 `@<team_leader_name>` ，再把事故任务复制到这条 @ 消息里发送。不要把事故任务发给 `manager` 。 `manager` 用于创建和管理 Agent/Team；Team 房间中的 leader 用于接收业务任务并调度 Worker。

请逐个任务发送：先发送第一起事故，等 `INC-1001` 事故报告完整输出后，再发送第二起事故。不要同时发送两条事故任务，避免 Team 并发调度时上下文和工具状态互相干扰。

每条消息只包含用户能自然提供的故障现象和少量初始告警。

Agent 会通过工具网关主动查询日志、Trace、配置变更、慢 SQL、Runbook、恢复指标等信息，完成任务。

## 步骤七：思考自己的使用场景，并了解AgentTeams的能力

AgentTeams 可以让多个 OpenClaw 协同完成任务，并为不同 Agent 设置明确分工。

OpenClaw 能实现的大部分能力，都可以迁移到 AgentTeams 中，并通过多角色协作进一步拆解复杂任务。

因此，在使用 AgentTeams 时，可以参考现有的 OpenClaw 教程、工具和案例。
